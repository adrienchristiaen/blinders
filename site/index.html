Start your agents blind.Open only what the prompt needs.

Foveate starts Claude Code, Gemini CLI, Codex or Mistral Vibe in an empty workspace with a short index of your repos. It opens the repos your prompt names, the related ones it needs, and the MCP servers it will use. Everything else stays closed.

Running an agent at the root of everything loads everything it can find.

Agent CLIs read the context files, MCP servers and skills they find when they start. Start one above many repos and you pay for all of it on every prompt, including the repos the question never touches.

Started at the root of your repos

~/work/
├─ repo-a/  its CLAUDE.md, GEMINI.md, AGENTS.md
├─ repo-b/  its CLAUDE.md, GEMINI.md, AGENTS.md
├─ ...every repo you have
└─ plus every MCP server and skill you configured

Everything is in scope, so everything is a candidate for the context window.

Started with Foveate

~/.cache/blinders/sessions/
├─ AGENTS.md  CLAUDE.md  GEMINI.md  one short index
├─ + the repos your prompt needs
└─ + the MCP servers it will use

The agent sees a map of your repos, not their contents. You open more when the question widens.

Index, select, open. No model call in between.

Foveate never opens application source to decide what to open. It reads each repo's README start, folder names and build or deploy files once, then ranks the repos in milliseconds.

  1. Index your repos

    One scan of the folders you point it at. For each repo it keeps the README start, the top-level folder names and markers such as pom.xml, dbt_project.yml or Chart.yaml. It refreshes itself daily.

    $ blind init ~/work ~/perso
indexed <n> repos (<m> links)

  2. Select from the prompt

    A repo named in the prompt wins. Otherwise repos are ranked by how well their README and folder names match. If nothing matches, the session stays fully blind.

    $ blind select "fix the airflow dag"
nightly-pipelines  open  (terms: airflow, dag)

  3. Open with the CLI's own options

    The agent starts in a throwaway workspace that holds the index. The chosen repos are added with the options each CLI already has. Nothing in your configuration is modified.

    $ blind run gemini --dry-run "lineage of sales-api-java"
cd ~/.cache/blinders/sessions/... && gemini \
  --include-directories ~/work/sales-api-java \
  -i 'lineage of sales-api-java'

Repo names in these examples are made up. The last block is the real shape of the command.

An application is rarely alone. Foveate finds the repos around it.

While indexing, it reads build and deploy files only: Helm charts, Kubernetes manifests, Dockerfiles, CI, Terraform, pom.xml, package.json. When one repo mentions another by name, they are linked. You can also declare groups in config.toml.

references it in helm/values.yaml

Words like deploy, helm or kubernetes open the related repo whose role is deploy. Words like lineage or dbt do the same for data repos.

Prefer to open the strongest related repos every time? blind run gemini --related all "...". Prefer none? --related none.

Only the MCP servers the prompt will use.

Every MCP server adds its tool descriptions to the context. Foveate matches your servers to the prompt by name, command, address and description, and starts the CLI with the ones that match. The others are listed in the index so the agent can ask for them.

Gemini CLI
On by default. Uses --allowed-mcp-server-names and leaves the rest of your settings alone.
Claude Code
Only when you pass --mcp. It starts with a file holding just the chosen servers, so plugins and connectors outside that file are not loaded either.
Your say
Keep some servers always with [mcp] always, add match words with [mcp.keywords], or override once with --mcp all, none or a list of names.

blind mcp --cli gemini fix the bigquery load

keep  bigquery  (prompt mentions bigquery)
drop  github
drop  jira

# index.md, "MCP servers not loaded":
github, jira
Ask the user to restart with --mcp if one is needed.

Optional: a code graph for the repos you open.

Foveate does not need a graph. If you use Graphify, blind graph --all builds one per repo with graphify extract --code-only --global. That parses code locally with no API key and also merges each repo into Graphify's global graph. When a repo has a graph report, the index tells the agent to read it before searching files.

Build once, refresh when you want

$ uv tool install graphifyy
$ blind graph sales-api-java
$ blind graph --all --update

Before you rely on it

  • CLI options were checked for Claude Code and Gemini CLI against their --help. The Codex and Mistral Vibe adapters were not. Run with --dry-run and adjust the adapter in config.toml if your version differs.
  • The in-session commands in the index are not verified. The index tells the agent to ask you for /add-dir (Claude Code) or /directory add (Gemini CLI). Check them on your version.
  • Blind by construction, not by enforcement. The agent cannot see repos you did not open, but it can still read anything it can reach, such as your home directory.
  • Selection is lexical. It looks at repo names, README text, folder names and build files. A prompt that shares no word with a repo will not open it. Name the repo or declare a group.
  • Skill and MCP filtering covers user-level entries only, not those that come from plugins or extensions. The skill settings used for Claude Code and Gemini CLI come from their docs and issue trackers and have not been tested on a real session. Gemini applies workspace settings only in a folder you trust.
  • Token numbers are estimates. blind audit counts characters divided by four and does not measure MCP tool descriptions.

Questions

Does it change my Gemini or Claude configuration?

No. It works through launch options. The files it writes live in ~/.cache/blinders and are deleted after seven days, or now with blind clean. With --mcp on Claude Code, a copy of the chosen servers' configuration, which may include tokens, is written there with owner-only permissions.

Does anything leave my machine?

Foveate makes no network calls and has no telemetry. Graphify is a separate tool you run yourself; with --code-only it parses code locally.

Why not just start the agent inside one repo?

You can: blind run claude --primary -r my-repo does exactly that and keeps the repo's own project settings. The default workspace adds what a single repo cannot give you: a map of the other repos, related repos, and a trimmed MCP list.

What happens when the agent needs a repo that is closed?

The index lists every closed repo with its path and tells the agent to ask you to add it. You add it in the session, or restart with blind run <cli> -r <repo>.

Why "Foveate"?

The fovea is the part of the retina that sees sharply. To foveate is to look straight at something. The project is still called blinders in the repository and the command is blind.
